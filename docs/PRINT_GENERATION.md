
# Print Generation

## 1. Overview

PrintForge generates print-ready files using a server-side production engine.

Supported outputs include:
- PDF
- PNG
- Individual variable-data PDFs

The browser designer is used for editing and previews. Final production files must be generated or validated on the backend.

## 2. Supported Input Formats

Initial supported formats:
- PDF
- PNG
- JPEG
- WebP
- SVG

Additional formats such as AI and EPS require a compatible conversion pipeline before production.

## 3. Print Specifications

Print settings are defined per product.

Important settings:
- Width
- Height
- Measurement unit
- Resolution
- Bleed
- Safe margin
- Background
- Output format

The product database is the authoritative source for print specifications.

## 4. Resolution

Default target:

300 DPI

Required pixel dimensions:

Pixels = (Millimetres / 25.4) × DPI

Example:

100 mm at 300 DPI:

(100 / 25.4) × 300 = approximately 1181 pixels

Increasing output dimensions does not create missing image detail.

Raster artwork must be checked for effective resolution before production.

## 5. Bleed

Bleed extends artwork beyond the final trim boundary.

Example:

Final width: 100 mm

Bleed: 3 mm per side

Total output width: 106 mm

Final output dimensions must include bleed.

## 6. Safe Margin

Important content should remain inside the safe area.

Safe Margin protects:
- Text
- Logos
- QR codes
- Important graphics

The safe margin must be calculated from the actual product specification.

## 7. Artwork Validation

Before generation:

1. Validate file format.
2. Validate file size.
3. Parse artwork.
4. Inspect document dimensions.
5. Validate printable boundaries.
6. Check bleed requirements.
7. Check effective image resolution.
8. Check unsupported fonts or objects.
9. Reject invalid artwork.

## 8. PDF Generation

The PDF generator uses pdf-lib.

Responsibilities:
- Create physical page dimensions.
- Import supported source artwork.
- Apply bleed.
- Position artwork.
- Preserve supported vector content.
- Generate downloadable PDF files.

PDF source compatibility and font behavior must be tested with representative customer files.

## 9. PNG Generation

The PNG generator uses Sharp.

Responsibilities:
- Resize to required pixel dimensions.
- Apply background.
- Include bleed.
- Generate the requested output format.
- Preserve suitable image quality.

Resolution metadata should be embedded where supported.

## 10. Variable-Data Printing

Variable-data printing uses:
- A print template.
- CSV data.
- Placeholder definitions.
- Font configuration.
- Position and sizing rules.

Workflow:

1. Upload CSV.
2. Parse CSV headers.
3. Validate required fields.
4. Reject invalid rows.
5. Load template.
6. Replace placeholders.
7. Fit text to available space.
8. Generate one output per valid row.
9. Record row-level errors.
10. Upload generated files.

## 11. Text Fitting

The text fitter supports:
- Maximum font size.
- Minimum font size.
- Shrink-to-fit.
- Character spacing.
- Text width constraints.

If text cannot fit within the permitted minimum font size, the row must be reported as invalid rather than silently clipped.

## 12. Output Naming

Suggested structure:

OrderID_ProductType_Date_Output

Example:

PF-20261120-A1B2C3D4_Labels_20261120_PrintReady.pdf

Output folders must be generated by the backend.

## 13. Production Gate

Production generation requires:

- Valid order.
- Successful payment.
- Approved latest proof.
- Valid artwork.
- Valid production configuration.

The backend must enforce these conditions regardless of frontend state.

## 14. Storage

Generated files are uploaded to private storage.

Database records contain:
- File name.
- Storage path.
- File type.
- File size.
- Order ID.
- Customer ID.
- Generation status.
- Print metadata.

Customers must not receive direct access to production files unless a specific business rule permits it.

## 15. Reliability

Production jobs should support:
- Idempotency.
- Retry handling.
- Failure logging.
- Job status tracking.
- Temporary-file cleanup.
- Duplicate prevention.
- Output integrity checks.

## 16. Quality Assurance

Test representative files for:
- Correct physical dimensions.
- Correct bleed.
- Safe margins.
- Resolution.
- Fonts.
- Vector preservation.
- Text placement.
- CSV row accuracy.
- File integrity.
